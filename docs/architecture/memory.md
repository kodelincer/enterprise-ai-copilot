# لایه‌های حافظه و دانش

## سه نوع داده، سه روش دسترسی

| نوع اطلاعات | روش دسترسی |
|---|---|
| اسناد، قراردادها و نامه‌های PDF | Document RAG |
| مکالمات، مذاکرات و تصمیم‌های گذشته | Honcho + آرشیو جلسات |
| وضعیت فعلی درخواست تعمیر، نامه یا قرارداد | API مستقیم سامانه مربوطه |

!!! danger "قاعده"
    داده زنده هرگز از Embedding خوانده نمی‌شود. سؤال «الان چند درخواست تعمیر باز داریم؟» باید مستقیم به CMMS برود.
    اما سؤال «چرا این خرابی تکرار شده؟» نیازمند تحلیل ترکیبی داده CMMS، گزارش تعمیرات، قرارداد و مکاتبات است.

## چهار لایه حافظه

1. **Conversation Memory** — مکالمات و سوابق تعامل با معاون؛ **Honcho**.
2. **Organizational Knowledge** — اسناد، قراردادها، نامه‌ها، بخشنامه‌ها و دستورالعمل‌ها؛ **Document RAG**.
3. **Operational Knowledge** — وضعیت زنده سیستم‌های عملیاتی؛ **API و دیتابیس سامانه‌ها**.
4. **Decision & Event History** — ثبت تصمیم‌ها، اقدامات، مسئولیت‌ها و نتیجه اجرای آن‌ها؛ **مخزن ساختاریافته و قابل ردیابی**.

## لایه پنجم: دانش ترکیبی (LLM Wiki)

علاوه بر چهار لایه بالا، یک **ویکی Markdown** که Agent از روی اسناد می‌سازد و نگه می‌دارد، دانش به‌هم‌پیوسته و در حال تکامل (سابقه موجودیت‌ها، موضوعات، جمع‌بندی‌ها) را نگه می‌دارد. **مخزن اسناد اصلی** تغییرناپذیر و منبع حقیقت است؛ ویکی همیشه به آن ارجاع می‌دهد. جزئیات: [دانش ترکیبی](llm-wiki.md).

## نکته درباره Honcho

Honcho را نباید بدون بررسی قابلیت‌های چندکاربره، کنترل دسترسی و جداسازی داده‌ها به‌عنوان حافظه اصلی کل سازمان در نظر گرفت. ممکن است برای **حافظه شخصی معاون** عالی باشد، ولی حافظه رسمی و سازمانی باید ساختار و مالکیت مستقل داشته باشد.

یافته‌های تحقیق (۱۴۰۵/۰۸/۳۰) درباره Honcho:

- قابل نصب محلی (Self-host) با Docker Compose؛ نیازمند **PostgreSQL + pgvector**؛ Redis اختیاری.
- مدل داده: Workspace (جداسازی کاربردها)، Peer (انسان یا AI)، Session، Scope، Message.
- حالت چندمستاجری با Row-Level Security در Postgres وجود دارد، اما **احراز هویت به‌طور پیش‌فرض خاموش است** و باید فعال شود.
- **مجوز AGPL-3.0**: پیمانکار باید پیامدهای حقوقی (به‌ویژه در صورت تغییر کد) را بررسی کند.
- به یک LLM با قابلیت Tool-calling و مدل Embedding نیاز دارد؛ با Endpointهای سازگار با OpenAI مثل vLLM و Ollama کار می‌کند، پس می‌تواند کاملاً داخلی اجرا شود.
- به‌عنوان افزونه حافظه در Hermes Agent پشتیبانی می‌شود.
