## گزینه‌های فناوری به تفکیک لایه (نامزدها و انتخاب فاز ۱) {#candidates}

!!! tip "اصل"
    همه این فناوری‌ها را هم‌زمان مستقر نمی‌کنیم. با **تعداد کمی سرویس با تعریف روشن** شروع می‌کنیم و فقط وقتی نیاز اندازه‌گیری‌شده‌ای پیدا شد، مؤلفه جدید اضافه می‌شود. این جدول **نامزدها** را نشان می‌دهد، نه الزام به استقرار همه.

| لایه | نامزدها | کاربرد | انتخاب فاز ۱ | ارزیابی (فارسی و استقرار داخلی) |
|---|---|---|---|---|
| ذخیره اسناد اصلی | ذخیره‌ساز سازگار با S3 (MinIO، SeaweedFS، Ceph RGW) | فایل‌های اصلی تغییرناپذیر | ✅ یک ذخیره‌ساز S3 | کاملاً داخلی. وضعیت مجوز و پشتیبانی نسخه رایگان MinIO اخیراً تغییر کرده و پیمانکار باید بررسی کند؛ SeaweedFS و Ceph جایگزین‌اند |
| فراداده و حقایق | PostgreSQL | اسناد، موجودیت‌ها، روابط، منشأ (Provenance)، مخزن حقوقی، رویدادها | ✅ **پایگاه داده مرکزی** | داخلی؛ هسته سیستم |
| پردازش اسناد | Docling، Unstructured | PDF، Office، استخراج چیدمان صفحه و جدول | ✅ Docling (+ Unstructured در صورت نیاز) | هر دو متن‌باز و داخلی. کیفیت OCR فارسی به موتور OCR بستگی دارد و باید روی نامه‌های اسکن‌شده واقعی سنجیده شود ([پیوست‌ها](../requirements/attachments.md)) |
| Embedding | BGE-M3 یا مدل چندزبانه دیگر (مثلاً Qwen3-Embedding) | بازنمایی معنایی | ✅ BGE-M3 (پس از ارزیابی) | چندزبانه با پشتیبانی فارسی، اسناد طولانی و خروجی Dense و Sparse. محلی روی GPU متوسط. **باید با پرسش‌های واقعی فارسی ارزیابی و با یک مدل دیگر مقایسه شود** |
| جست‌وجوی متنی (BM25) | PostgreSQL FTS، OpenSearch | بازیابی واژگانی (شماره نامه، شماره ماده، اسامی) | ✅ PostgreSQL FTS | رتبه‌بندی داخلی PostgreSQL (`ts_rank`) دقیقاً BM25 نیست؛ برای BM25 واقعی افزونه‌ای مثل `pg_search` (ParadeDB) باید سنجیده شود ([توضیح BM25](../learn/bm25.md)). PostgreSQL ریشه‌یاب فارسی ندارد، پس نرمال‌سازی (ی/ي، ک/ك، نیم‌فاصله) پیش از نمایه‌سازی لازم است. OpenSearch تحلیلگر فارسی دارد ولی یک سرویس سنگین اضافه است؛ فقط اگر کیفیت PostgreSQL کافی نبود |
| جست‌وجوی برداری | pgvector، Qdrant | جست‌وجوی شباهت | ✅ pgvector | نیاز به پایگاه داده برداری جدا را در شروع حذف می‌کند و فیلتر فراداده و کنترل دسترسی در همان PostgreSQL است. Qdrant برای وقتی که حجم یا سرعت مشکل شود |
| ویکی دانش | Markdown + Obsidian | دانش ترکیبی قابل خواندن برای انسان | ✅ Markdown در git داخلی؛ Obsidian اختیاری | Obsidian Sync ابری است و نباید استفاده شود. [دانش ترکیبی](llm-wiki.md) |
| جست‌وجوی ویکی | QMD | جست‌وجوی ترکیبی روی ویکی | 🔍 **ارزیابی جداگانه** | برای سمت ویکی جذاب است، ولی **جدا از سیستم جست‌وجوی اسناد اصلی** ارزیابی می‌شود. مدل Embedding باید چندزبانه تنظیم و مدل‌ها آفلاین نصب شوند |
| Agent | Hermes | ارکستراسیون و اجرای ابزار | ✅ | داخلی؛ LLM از طریق دروازه |
| حافظه Agent | Honcho | زمینه مکالمه و کارها | ⏳ فاز ۲ | مجوز AGPL؛ احراز هویت باید فعال شود |
| ارزیابی کیفیت | Ragas، ارزیاب‌های Haystack | سنجش کیفیت بازیابی و پاسخ | ✅ Ragas از ابتدا | به یک **مجموعه آزمون فارسی** از پرسش‌های واقعی دفتر معاونت با پاسخ مرجع نیاز است. داوری با LLM همان قاعده ارسال داده به LLM بیرونی را دارد |
| خط لوله بازیابی | Haystack | خط لوله ماژولار پایتونی برای بازیابی و Agent | 🔍 بررسی | Haystack بین **خط لوله قطعی** (Pipeline) و **Agent پویا** تفاوت می‌گذارد. پیشنهاد: Haystack برای خط لوله‌های قطعی (ingest، بازیابی ترکیبی، بازرتبه‌بندی) و Hermes برای Agent. باید مراقب هم‌پوشانی دو چارچوب بود |
| بازیابی گرافی | GraphRAG (Microsoft)، جایگزین‌های سبک‌تر مثل LightRAG | کشف الگوهای کلی و اتصال موجودیت‌های زیاد | ⏳ بعداً | GraphRAG گراف دانش استخراج می‌کند، جوامع می‌سازد و برایشان خلاصه می‌نویسد. نمایه‌سازی آن **پرهزینه** است (فراخوانی زیاد LLM که با LLM بیرونی یعنی ارسال حجم زیاد متن). با گراف ساده روی PostgreSQL شروع می‌کنیم |

### هسته پیشنهادی فاز ۱ (حداقل سرویس‌ها)

1. **ذخیره‌ساز S3** برای اسناد اصلی
2. **PostgreSQL** (+ pgvector + FTS): فراداده، روابط، منشأ، جست‌وجوی ترکیبی، مخزن حقوقی، گراف
3. **سرویس پردازش اسناد** (Docling + OCR فارسی)
4. **سرویس Embedding** (BGE-M3 روی GPU داخلی)
5. **Hermes** + دروازه LLM
6. **مخزن git ویکی** (و QMD در صورت موفقیت ارزیابی)
7. **Ragas** با مجموعه آزمون فارسی

افزودنی‌های بعدی فقط با دلیل اندازه‌گیری‌شده: Honcho (فاز ۲)، OpenSearch، Qdrant، GraphRAG.

منابع: [BGE-M3](https://huggingface.co/BAAI/bge-m3)، [Docling](https://github.com/docling-project/docling)، [Unstructured](https://github.com/Unstructured-IO/unstructured)، [pgvector](https://github.com/pgvector/pgvector)، [Qdrant](https://github.com/qdrant/qdrant)، [Ragas](https://github.com/explodinggradients/ragas)، [Haystack](https://haystack.deepset.ai/)، [Microsoft GraphRAG](https://microsoft.github.io/graphrag/)
