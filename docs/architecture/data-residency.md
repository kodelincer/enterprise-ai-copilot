# نگهداری داده در سازمان (On-Premises)

!!! danger "اصل الزامی"
    **همه دانش، داده و ذخیره‌سازی باید داخل سازمان (On-Premises) باشد.** هیچ داده، سند، صوت، متن جلسه، Embedding، حافظه یا لاگی بیرون از سازمان ذخیره نمی‌شود.
    **تنها استثنا: موتور استدلال (LLM Inference)** که می‌تواند به‌صورت وب‌سرویس بیرونی استفاده شود.

## چه چیزی کجا اجرا می‌شود

| مؤلفه | محل |
|---|---|
| پایگاه داده، مخزن اسناد، گراف دانش، رویدادها | داخل سازمان |
| Embedding و جست‌وجوی برداری | داخل سازمان |
| OCR و استخراج پیوست‌ها | داخل سازمان |
| گفتار به متن و تشخیص گوینده | داخل سازمان |
| حافظه مکالمات (Honcho) | داخل سازمان |
| مهارت‌ها و MCPهای خودساخته | داخل سازمان |
| لاگ‌ها و ممیزی | داخل سازمان |
| **استدلال LLM** | **مجاز: وب‌سرویس بیرونی** یا مدل محلی |

## پیامدهای طراحی

- **دروازه LLM (LLM Gateway):** همه درخواست‌ها به مدل از یک دروازه واحد (مثلاً LiteLLM) عبور کنند تا بتوان بین ارائه‌دهنده بیرونی و مدل محلی بدون تغییر کد جابه‌جا شد.
- **حداقل‌سازی داده ارسالی:** فقط بخش لازم از متن برای هر درخواست به مدل فرستاده شود، نه کل اسناد.
- **قابلیت حذف/پنهان‌سازی:** امکان پنهان‌سازی اطلاعات حساس (نام اشخاص، شماره‌ها) پیش از ارسال، با تنظیم بر اساس طبقه‌بندی سند.
- **عدم نگهداری نزد ارائه‌دهنده:** ترجیحاً سرویسی که سیاست عدم ذخیره (Zero data retention) دارد.
- **لاگ کامل درخواست‌ها** داخل سازمان: چه داده‌ای، کی، به کدام مدل فرستاده شده.
- **مسیر جایگزین محلی:** در صورت قطع دسترسی به سرویس بیرونی یا برای اسناد طبقه‌بندی‌شده، مدل محلی (مثلاً Qwen روی vLLM) استفاده شود.

!!! warning "نکته برای تصمیم"
    حتی اگر سرویس بیرونی داده را ذخیره نکند، متن مربوط به هر درخواست در لحظه استدلال از سازمان خارج می‌شود. باید مشخص شود کدام سطح طبقه‌بندی اسناد مجاز به ارسال است. ([سؤالات باز](../open-questions.md))
