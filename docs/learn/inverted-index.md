# نمایه معکوس (Inverted Index)

!!! abstract "در یک جمله"
    **نمایه معکوس** ساختار داده‌ای است که جست‌وجوی کلیدواژه‌ای را سریع می‌کند: به‌جای اینکه برای هر سؤال همه سندها را بخوانیم، از قبل برای **هر کلمه** فهرست سندهایی را که آن کلمه را دارند نگه می‌داریم. پایه BM25 و همه موتورهای جست‌وجوی متنی است.

## ایده با یک تشبیه

**نمایه انتهای کتاب** را تصور کنید: «یاتاقان ← صفحات ۴۲، ۸۷، ۱۵۳». برای پیدا کردن «یاتاقان» کل کتاب را ورق نمی‌زنید؛ به نمایه نگاه می‌کنید. نمایه معکوس همین است، برای هزاران سند.

چرا «معکوس»؟ چون حالت عادی «سند ← کلمات داخلش» است؛ نمایه معکوس این را برعکس می‌کند: «کلمه ← سندهایی که آن را دارند».

## مثال

سه سند:

| سند | متن |
|---|---|
| D1 | خرابی پمپ ایستگاه زند |
| D2 | تعمیر پمپ ایستگاه شهدا |
| D3 | خرابی پله برقی ایستگاه زند |

نمایه معکوس:

| کلمه | فهرست سندها (Posting list) |
|---|---|
| خرابی | D1، D3 |
| پمپ | D1، D2 |
| ایستگاه | D1، D2، D3 |
| زند | D1، D3 |
| تعمیر | D2 |
| شهدا | D2 |
| پله | D3 |
| برقی | D3 |

پرسش «خرابی پمپ»:

1. فهرست «خرابی» → {D1، D3}
2. فهرست «پمپ» → {D1، D2}
3. سندهای نامزد → {D1، D2، D3}؛ D1 هر دو کلمه را دارد.

فقط **دو فهرست کوتاه** خوانده شد، نه کل متن سندها. با میلیون‌ها سند هم همین‌قدر سریع است.

## نمایه چه اطلاعات دیگری نگه می‌دارد؟

برای BM25 علاوه بر «کدام سند»، این‌ها هم ذخیره می‌شوند:

| اطلاعات | کاربرد |
|---|---|
| تعداد تکرار کلمه در هر سند (TF) | امتیاز BM25 |
| تعداد سندهای دارای کلمه (DF) | محاسبه IDF |
| طول هر سند | نرمال‌سازی طول در BM25 |
| موقعیت کلمه در سند | جست‌وجوی عبارت دقیق («پله برقی» کنار هم) و نزدیکی کلمات |

## ساخت نمایه: مرحله تقطیع (Tokenization)

پیش از ساخت نمایه، متن باید به کلمه (Token) شکسته و یکسان‌سازی شود. **این مرحله برای فارسی حیاتی است:**

| مشکل | بدون یکسان‌سازی | نتیجه |
|---|---|---|
| «ي» عربی و «ی» فارسی | «خرابي» و «خرابی» دو کلمه جدا می‌شوند | سند با «ي» پیدا نمی‌شود |
| نیم‌فاصله | «پمپ‌ها»، «پمپها»، «پمپ ها» | سه شکل متفاوت |
| پسوند | «پمپ» و «پمپ‌ها» | بدون ریشه‌یابی، جست‌وجوی «پمپ» شاید «پمپ‌ها» را نیابد |
| کد تجهیز | `VM-023` ممکن است به `VM` و `023` شکسته شود | باید قاعده خاص برای کدها داشت |

## نمایه معکوس در ابزارهای پروژه

| ابزار | نمایه معکوس |
|---|---|
| PostgreSQL FTS | نوع داده `tsvector` + نمایه `GIN` |
| SQLite FTS5 (داخل QMD) | جدول مجازی FTS5 |
| OpenSearch / Elasticsearch | بر پایه Lucene؛ نمایه معکوس هسته آن است |

## نمایه معکوس در برابر نمایه برداری

| | نمایه معکوس | نمایه برداری |
|---|---|---|
| کلید | کلمه | بردار معنایی |
| پرسش | «کدام سندها این کلمه را دارند؟» | «کدام تکه‌ها از نظر معنا به این نزدیک‌اند؟» |
| ساختار رایج | Posting list | HNSW و ساختارهای نزدیک‌ترین همسایه |
| مثال در پروژه | PostgreSQL GIN، SQLite FTS5 | pgvector، نمایه برداری QMD |
